## 0. 结论先行

建议采用：

> **Python 3.12 + PySide6 桌面界面 + OpenAI 兼容 SDK + Pydantic 结构化校验 + Jinja2 模板 + XeLaTeX / latexmk 编译 + 内嵌 PDF 预览**

其中最关键的一条原则是：

> **大模型只负责“读懂论文并标注结构”，不直接生成最终 LaTeX；LaTeX 由程序按照固定模板渲染。**

这样做的好处是：格式稳定、可回归测试、不会因为模型偶发输出而导致编译失败；同时模型仍然承担最擅长的工作——识别标题、摘要、章节、图表引用、作者信息和参考文献。

## 1. 产品定位

### 1.1 目标

做一款 **本地运行的 Windows 图形化论文排版工具**，让用户用向导完成：

1. 配置 OpenAI 兼容 API（默认 DeepSeek）；
2. 检测并引导安装 XeLaTeX；
3. 导入 TXT / Markdown 论文；
4. 由大模型识别论文结构和图表位置；
5. 人工核对结构、上传图片、编辑表格；
6. 填写作者、单位、作者简介、基金等信息；
7. 选择国标或通用模板、单栏或双栏；
8. 生成 `.tex`，调用 XeLaTeX 编译出 PDF；
9. 在软件内预览，导出 PDF、TEX 和完整资源包。

### 1.2 首版不做的事

明确排除，避免范围失控：

- 不做 AI 代写、润色、降重、伪造参考文献；
- 不承诺“一键完全符合某本期刊”，具体期刊/学校模板必须有其格式文件或样例；
- 不支持 DOCX/DOC、PDF（含扫描版）、知网 CAJ 作为正文输入；
- 不自动把 DOCX 转成 Markdown，也不做 OOXML、图片、表格的深度解析；
- 不自动转换复杂公式；Markdown 中显式的 `$...$` / `$$...$$` 按公式边界处理，纯 TXT 公式标记后由用户补 LaTeX；
- 不静默安装 TeX Live / MiKTeX，不做需要管理员权限的后台安装；
- 不做 macOS / Linux、云同步、多人协作、在线模板市场；
- 不把 LaTeX 发行版打包进安装包。

## 2. 关键设计决策

| # | 决策 | 方案 | 理由 |
|---|---|---|---|
| 1 | 桌面技术 | PySide6 / Qt 6 | 原生 Windows 体验、文件拖拽、后台任务、PDF 预览成熟；Python 生态适合文档解析和 API 调用 |
| 2 | AI 的边界 | AI 输出语义 JSON，程序渲染 LaTeX | 避免模型直接写 LaTeX 带来的编译不稳定和安全风险 |
| 3 | 内容保真 | 原文按块编号，AI 只返回块 ID 和角色 | 可校验“无遗漏、无重复、未被改写” |
| 4 | 模板 | 模板 = 配置清单 + Jinja2 模板 + `.sty` + 资源 | 新增学校/期刊格式时只加模板，不改核心代码 |
| 5 | 国标落地 | “结构规范检查”与“版式参数”分离 | GB/T 7713.2 主要规定组成部分和编排规则，具体字号字体是资料性附录，不能简单等同于一套固定版式 |
| 6 | 编译 | 外部 XeLaTeX，优先 latexmk | 不捆绑巨型 TeX 发行版；latexmk 自动处理交叉引用和参考文献 |
| 7 | PDF 预览 | pypdfium2 渲染到 Qt | 比 QtPdf 依赖轻，避免 PyMuPDF 的 AGPL 许可问题 |
| 8 | 密钥 | Windows 凭据管理器（keyring） | 不把 API Key 写入项目、日志或导出包 |
| 9 | 打包 | PyInstaller onedir + Inno Setup | 启动快、体积可控、便于覆盖升级；比 onefile 更少被杀软误报 |
| 10 | 项目存储 | 项目目录 + JSON + assets | 易调试、可迁移、可直接导出 ZIP；首版不需要数据库 |
| 11 | 输入格式 | TXT + Markdown | 避开 OOXML/图片/表格解析的高复杂度；M2 可减少约 5–6 天 |

### 5.2 线程与任务

- UI 线程只做界面，不执行 API、文档解析和编译。
- 使用 `QThreadPool` + `QRunnable`，统一 `TaskHandle` 支持进度、取消、错误。
- 同一时间只允许一个“重任务”，避免用户连续点击导致项目状态竞争。
- API 调用和编译子进程均设置超时；取消时终止子进程，保留日志。
- 项目写盘采用临时文件 + 原子替换，防止崩溃损坏。

## 6. 核心数据模型

```text
Project
├─ schema_version
├─ source: 原始文件副本
├─ document: DocumentIR
│  ├─ blocks[]: 每个内容块
│  └─ sections[]: 章节树
├─ metadata
├─ figures[]
├─ tables[]
├─ references[]
├─ layout
├─ build_history[]
└─ created_at / updated_at
```

### 6.1 内容块 Block

```json
{
  "id": "B0007",
  "kind": "paragraph",
  "text": "本文研究流程如图1所示。",
  "heading_level": null,
  "runs": [
    {"text": "本文研究流程如", "bold": false, "italic": false, "code": false},
    {"text": "图1", "bold": true, "italic": false, "code": false}
  ],
  "source": {
    "file": "manuscript.md",
    "line_start": 42,
    "line_end": 42,
    "format": "markdown",
    "block_index": 6
  },
  "confidence": 0.98,
  "warnings": []
}
```

`kind` 的取值固定为：`title`、`subtitle`、`author`、`affiliation`、`abstract`、`keywords`、`heading`、`paragraph`、`list`、`code`、`figure_caption`、`table_caption`、`table`、`algorithm`、`equation`、`reference`、`acknowledgement`、`appendix`、`unknown`。

- `heading_level` 支持 1–4 级；第 4 级可映射为 `\paragraph`。
- `runs` 保留 Markdown 的 `**bold**`、`*italic*`、`` `code` ``；颜色和字号不继承，由模板决定。
- TXT 没有富文本，`runs` 与 `text` 相同。
- Markdown 的 `$...$` / `$$...$$` 进入 `equation` 块；纯 TXT 公式标记后由用户补 LaTeX。
- 图片块与表格块通过 Markdown token 或用户上传建立，不从 DOCX 提取。

### 6.2 图表对象

```json
{
  "id": "fig_001",
  "type": "figure",
  "label": "图1",
  "caption": "研究流程图",
  "anchor_after_block": "B0007",
  "reference_block_ids": ["B0007"],
  "asset_path": "assets/figures/fig_001.png",
  "source": "user_upload",
  "width_ratio": 0.8,
  "span_columns": false,
  "placement": "htbp",
  "status": "ready"
}
```

关键点：

- “图1”是**对象**，不是每次出现都插图；正文中可以有多个引用块。
- `anchor_after_block` 是源码插入锚点，不等于最终页面位置。
- 双栏下 `span_columns=true` 使用 `figure*` / `table*`；浮动位置由 LaTeX 决定。
- 缺图时状态为 `missing`，允许先生成带占位框的 PDF，导出前给警告。

### 6.3 参考文献条目

```json
{
  "id": "ref001",
  "original_text": "Bate R R, Mueller D D, White J E. Fundamentals of Astrodynamics...",
  "type": "book",
  "authors": ["Bate R R", "Mueller D D", "White J E"],
  "title": "Fundamentals of Astrodynamics",
  "journal": null,
  "booktitle": null,
  "publisher": "Dover Publications",
  "address": "New York",
  "year": "1971",
  "volume": null,
  "number": null,
  "pages": null,
  "doi": null,
  "language": "english",
  "citation_keys": ["Bate1971"],
  "confidence": 0.96,
  "missing_fields": [],
  "status": "confirmed"
}
```

- `original_text` 永远保留，用于回退和审计；
- `citation_keys` 保存正文中原本使用的标签；首版支持数字引用映射，作者-年份引用保留原文并提示；
- `status`：`pending`、`confirmed`、`fallback_text`；
- 缺失字段为 `null`，不得由模型填造。

### 6.4 校验不变量

生成前必须通过：

1. 每个非空源块都有归属，不能丢块；
2. 块 ID 不重复，章节树无环；
3. 图/表编号唯一，题注非空；
4. 所有图表引用都能找到对象；
5. 所有 `ready` 图表资源存在且格式受支持；
6. 标题、作者、摘要等必填项完整；
7. 每条参考文献有 ID、原文和类型；生成 `.bib` 的条目不能缺作者/标题等关键字段；
8. 正文数字引用映射到存在的 `citation_key`，无法映射的保留原文并警告；
9. 双栏下跨栏长表格/强制 `[H]` 等组合给出警告或禁用；
10. 所有文本完成 LaTeX 转义，图片路径在项目目录内；
11. 前置信息不重复：已由元数据表单吸收的正文块，渲染时必须跳过；
12. 正文候选与表单值不一致时，必须有明确的冲突记录或用户确认，不能静默覆盖。

### 6.5 元数据字段与“已吸收块”

```json
{
  "metadata": {
    "title": {
      "value": "基于深度学习的论文自动排版方法研究",
      "source": "body",
      "evidence_block_ids": ["B0001"],
      "confirmed": true
    },
    "authors": {
      "value": ["张三", "李四"],
      "source": "manual",
      "evidence_block_ids": ["B0002"],
      "confirmed": true
    },
    "affiliations": {
      "value": ["某某大学 计算机学院，上海 200000"],
      "source": "body",
      "evidence_block_ids": ["B0003"],
      "confirmed": true
    },
    "fund": {
      "enabled": true,
      "items": [
        {"name": "国家自然科学基金", "number": "62000000"}
      ],
      "source": "manual",
      "evidence_block_ids": ["B0021"],
      "confirmed": true
    },
    "consumed_block_ids": ["B0001", "B0002", "B0003", "B0021"]
  }
}
```

- `source`：`body`、`ai`、`manual`、`default`；
- `evidence_block_ids` 保存正文证据，支持“回退正文”和原文定位；
- `consumed_block_ids` 中的块仍保留在 IR 中，但生成前置部分时跳过；
- 覆盖校验把“已吸收块”视为已归属，不会误报丢块；
- 生成前若存在未确认的冲突，给出警告或阻止生成，具体见 10.3。

## 7. 文档导入设计

### 7.1 TXT

- 使用 `charset-normalizer` 检测 UTF-8、GB18030、GBK 等编码；
- 按空行分段，保留原始行号；
- 识别连续短行、全角空格、明显的页眉页脚噪声；
- 保留 `摘要`、`关键词`、`参考文献`、`图1`、`表1` 等标记，交给规则和模型判断；
- Tab / 多空格分隔的表格可识别为候选表格，其余表格进入手动编辑器；
- 原文中的 `[P001]` 类编号若已存在，避免二次编号冲突。

TXT 没有图片和表格结构，因此：

- 图片由用户在图表管理页上传；
- 表格由用户粘贴/编辑，或从 CSV/Excel 粘贴；
- AI 只负责定位“图1/表1 应该放在哪”，不重建表格数据。

### 7.2 Markdown

使用 `markdown-it-py` + `mdit-py-plugins` 解析 CommonMark/GFM token：

- 标题：`#`–`####` 映射为 1–4 级标题；首个 H1 可作为题名候选，最终由用户确认；
- 段落：保留段落边界和行号；
- 行内格式：`**bold**`、`*italic*`、`` `code` `` 转成 `runs`；
- 列表：简单有序/无序列表转成 `list` 块，嵌套列表首版降级为缩进文本；
- 引用块：转为普通段落并保留来源；
- 代码块：转为 `code` 块，渲染为等宽段落；
- 表格：GFM 管道表格转成结构化单元格；不支持合并单元格；
- 图片：`![图1 研究流程图](assets/fig1.png)` 生成图表对象，复制本地图片到项目 `assets/figures/`；
- 公式：`$...$` / `$$...$$` 通过 `mdit-py-plugins` 的 dollarmath 解析；只接受简单公式，危险命令降级为文本；
- 链接：保留链接文字，不自动抓取网页内容；
- 原始 HTML：默认剥离并给出警告，不执行、不渲染；
- 远程图片 URL：首版不自动下载，提示用户上传本地图片。

Markdown 图片规则：

```markdown
![图1 研究流程图](assets/fig1.png)
```

- 路径相对于 `.md` 文件解析；
- 只允许项目目录内的本地路径；
- 文件不存在 → 图表对象进入“待上传”；
- alt 文本优先作为题注；无法判断时由用户修改。

Markdown 表格规则：

```markdown
表1 不同方法的性能比较

| 方法 | 准确率/% | 召回率/% |
|---|---|---|
| 基线 | 90.1 | 88.7 |
| 本文 | 93.5 | 92.8 |
```

- 表题优先取表格前一行的 `表N ...`；
- 单元格按纯文本导入，行内格式降级；
- 合并单元格、嵌套表不支持，提示改用图片或手动表格。

### 7.3 规范化文本

提供给模型的是块 IR + 稳定 ID，不是原始 Markdown/HTML：

```text
[B0001] role=title | 基于深度学习的论文自动排版方法研究
[B0002] role=author | 张三，李四
[B0003] role=affiliation | 某某大学 计算机学院，上海 200000
[B0004] role=abstract | 摘要：本文……
[B0005] role=keywords | 关键词：自动排版；深度学习；XeLaTeX
[B0006] role=heading level=1 | 引言
[B0007] role=paragraph | 本文研究流程如图1所示。
[B0008] role=figure_caption | 图1 研究流程图
```

这样模型只做“分类和分组”，不接触原始排版，也便于程序逐块核对。

### 7.4 不支持内容的处理

| 内容 | 首版处理 |
|---|---|
| DOCX / DOC | 不支持；提示用户另存为 TXT 或 Markdown |
| PDF（含扫描版、图片型） | 不作为正文输入 |
| Markdown 原始 HTML | 剥离并警告，不执行 |
| 远程图片 URL | 不自动下载，提示上传本地图片 |
| 合并单元格 / 嵌套表格 | 不支持，提示改用图片或手动表格 |
| 复杂公式 / 危险 LaTeX 命令 | 降级为文本，提示用户手动处理 |
| 超大文档 | 分块处理，显示进度和 token 估算 |

## 8. 大模型设计

### 8.1 默认配置

| 配置 | 默认值 | 说明 |
|---|---|---|
| base_url | `https://api.deepseek.com` | 官方 OpenAI 兼容地址；用户可改 |
| model | `deepseek-flash` | 截至 2026-10-24 官方文档的通用模型；用户可改 |
| api_key | 空 | **软件不内置真实 Key**，首次启动由用户填写 |
| thinking | `{"type": "disabled"}` | 结构识别不需要思维链；默认关闭，降低延迟和费用 |
| temperature | 0.1 | 仅在非思考模式下生效；结构识别需要稳定 |
| response_format | `{"type": "json_object"}` | 启用 JSON Output；失败时回退到纯提示词 JSON |
| max_tokens | 16K（可调） | 按块数动态计算，避免 JSON 被截断 |
| timeout | 120 s / 请求 | 可配置 |
| 代理 | 默认读取系统代理 | 高级设置可手动填 HTTP/HTTPS 代理；不写入日志 |
| 重试 | 429/5xx 重试 2 次，指数退避 | 401/402/403/422 不重试 |
| 上下文 | 官方 1M，最大输出 384K | 首版不做极限压榨，仍按章节安全分块 |

> 关于“默认 DeepSeek 的 API Key”：这里理解为“默认服务商是 DeepSeek、预填官方 base_url 和默认模型”，不是把某个真实 Key 写进软件。真实 Key 必须由用户输入并保存在本机凭据管理器；否则分发即泄露。

连接测试使用一次 `max_tokens=8` 的极小 Chat 请求；DeepSeek 文档未把 `/models` 作为稳定能力，因此不依赖该端点。测试结果只显示状态，不回显 Key。

DeepSeek 官方 JSON Output 要求：设置 `response_format={'type':'json_object'}`，在 system/user prompt 中包含“json”并给出 JSON 示例，同时设置合理的 `max_tokens`。官方说明 JSON 模式偶尔可能返回空内容，因此程序必须做“空内容/解析失败”重试，失败后回退本地规则。

常见错误映射：

| HTTP / 情况 | 用户提示 | 程序动作 |
|---|---|---|
| 401 | API Key 无效或已失效 | 不重试，跳回设置页 |
| 402 | 账户余额不足 | 不重试，提示充值或换 Key |
| 403 | 无权限/模型不可用 | 不重试，提示检查模型名与账户权限 |
| 422 | 参数不合法 | 不重试，显示具体字段 |
| 429 | 请求过于频繁/并发限制 | 指数退避重试 2 次 |
| 5xx | 服务端临时错误 | 指数退避重试 2 次 |
| 超时/网络错误 | 无法连接 API | 提示检查网络、代理与 base_url |
| JSON 为空/截断 | 返回内容不完整 | 降低块大小/提高 max_tokens 后重试一次 |

### 8.2 模型职责

只做以下五件事：

1. 识别论文区域：题名、作者、单位、摘要、关键词、正文、参考文献、致谢、附录；
2. 识别章节层级和标题；
3. 识别图表题注、正文引用、建议锚点；
4. 抽取已有作者、单位、基金信息，供用户确认；
5. 将**已有**参考文献原文解析为结构化字段，供用户逐条确认；
6. 标记缺失、歧义、疑似非正文内容。

**禁止**：改写正文、补写内容、生成或补全参考文献、输出完整 LaTeX、输出 HTML/Markdown 作为最终排版。

### 8.3 返回格式

调用参数的核心组合：

```python
response = client.chat.completions.create(
    model="deepseek-flash",
    messages=messages,
    response_format={"type": "json_object"},
    temperature=0.1,
    max_tokens=16384,
    extra_body={"thinking": {"type": "disabled"}},
)
```

- 默认关闭 thinking：结构识别是分类任务，不需要长思维链；同时 thinking 模式下 `temperature` 不生效。
- 如果用户切换成 `deepseek-v4-pro` 或自定义模型，程序仍按同一接口调用；若服务端不支持 `response_format`，自动退化为提示词 JSON + 本地解析。
- 结构化结果示例（块 ID 只引用原文，不重复正文）：

```json
{
  "title": "基于深度学习的论文自动排版方法研究",
  "sections": [
    {
      "level": 1,
      "title": "引言",
      "block_ids": ["B0006", "B0007"]
    }
  ],
  "figures": [
    {
      "id": "fig_001",
      "label": "图1",
      "caption": "研究流程图",
      "caption_block_id": "B0008",
      "reference_block_ids": ["B0007"],
      "suggested_anchor_after": "B0007",
      "confidence": 0.96
    }
  ],
  "tables": [],
  "metadata_candidates": {
    "authors": ["张三", "李四"],
    "affiliations": ["某某大学 计算机学院，上海 200000"],
    "funds": []
  },
  "warnings": [
    {"code": "ambiguous_heading", "block_id": "B0012", "message": "该行可能是二级标题，也可能是正文"}
  ]
}
```

程序侧用 Pydantic 校验，并执行：

- 所有 ID 必须存在；
- 所有非空块必须被覆盖；
- 正文块原文字符串必须与输入一致（默认不允许模型改写）；
- 图表编号不能重复；
- 模型返回未知字段时丢弃并记录警告；
- JSON 解析失败时尝试一次修复/重试，仍失败则回退到本地规则并提示。

### 8.4 长文档

- DeepSeek 官方给出 1M 上下文，但首版不按“能塞就塞”设计；默认整篇处理，超过约 100k 汉字或 1500 个内容块时按章节分块；
- 分块时先识别目录/标题行，再按章节处理，避免把一章从中间切断；
- 每块都带全局块 ID，汇总时统一校验覆盖与重复；
- JSON 输出按块 ID 组织，不重复正文，控制输出 token；
- 失败保留已完成结果，支持“只重试失败章节”；
- UI 显示“本次将发送约 N 字 / 预计 token”，用户确认后再调用；
- 默认不把全文写入本地日志。

### 8.5 本地规则模式

即使不配置 API，也应能：

- 用正则识别常见标题、摘要、关键词、图/表题注；
- 用规则生成基础章节树；
- 手工完成结构校对。

这样 API 故障或用户不愿上传时，软件仍然可用。

## 9. 图表识别与输入

### 9.1 识别策略

三层：

1. **正则候选**：`图\s*\d+`、`图\s*\d+[-—.]\d+`、`表\s*\d+`、`表\s*\d+[-—.]\d+`、`Fig.`、`Figure`、`Table`、`见图`、`见表`、`如图`、`如表`；
2. **位置判断**：独立成行、居中对齐、以“图/表 + 编号 + 空格 + 标题”开头，优先判为题注；句子中出现多为引用；
3. **模型语义判断 + 用户确认**：区分题注、正文引用、图表清单、附录中的图。

首版约定：

- 图/表默认**全文连续编号**（图1、图2、表1、表2），也识别“图2-1 / 表3-2”这类按章编号，但生成时统一重排为全文连续编号；
- 一个图对象对应一张图片；`图1(a)`、`图1(b)` 这类子图首版不自动拆分，作为一张合成图处理，或在待处理项中提示用户合并；
- 同一图/表可被正文引用多次，但只生成一个图表对象。

### 9.2 图表管理页

列表字段：

| 字段 | 说明 |
|---|---|
| 编号 | 图1、表1；允许用户改号并全局重排 |
| 类型 | 图片 / 表格 / 图片型表格 |
| 题注 | 中文题注，可加英文题注 |
| 正文引用 | 显示引用段落，可跳转 |
| 素材状态 | Markdown 路径已关联 / 待上传 / 缺失 / 不适用 |
| 插入锚点 | 默认“引用段之后”，可手动改 |
| 跨栏 | 单栏宽 / 跨双栏 |
| 操作 | 上传、替换、预览、删除、定位 |

### 9.3 图片输入窗口

- 支持 PNG、JPG、JPEG；PDF 图片首版不支持，需先转成 PNG/JPG；
- Markdown `![]()` 本地路径自动关联；远程 URL 不自动下载；
- 拖拽或文件选择；
- 预览、尺寸、DPI/清晰度提示；
- 宽度比例（25%–100%）；
- 是否跨栏；
- 题注、英文题注、图注；Markdown alt 文本作为初值；
- 来源备注；
- 缺失时允许“生成占位框”，但导出前必须确认。

### 9.4 表格输入窗口

- Markdown 管道表格直接导入并结构化；
- TXT 表格通过粘贴、CSV/Excel 或手动编辑建立；
- 增删行列、合并单元格（首版有限支持）；
- 表题、表注、单位；
- 三线表样式；
- 跨栏、长表格、字号缩小；
- 纯截图表格按图片处理，并提示“文字不可编辑”；
- 首版只支持规则二维表和简单合并；复杂合并、嵌套表、跨页长表格若无法可靠渲染，转为待处理项，不静默丢内容；
- AI 只定位“表1 应插在哪”，**不根据语义重建表格数据**。

### 9.5 插入位置的正确表述

界面必须写清楚：

> “插入在某段之后”表示 LaTeX 源码中的锚点和优先位置，最终页面位置由浮动体和模板决定。软件会尽量让图表靠近引用处，但不承诺像素级固定。

这能避免用户误以为所见即所得。

## 10. 作者与基金信息

### 10.1 表单结构

| 信息组 | 字段 |
|---|---|
| 论文 | 中文标题、英文标题、副标题 |
| 作者 | 姓名、英文姓名、单位序号、通信作者、邮箱、排序 |
| 单位 | 中文名称、英文名称、部门、城市、邮编、国家 |
| 摘要 | 中文摘要、英文摘要 |
| 关键词 | 中文关键词（3–8 个）、英文关键词 |
| 作者简介 | 姓名、职称、学位、研究方向、简介文本 |
| 基金 | 启用开关、项目名称、项目编号、排序 |
| 其他 | 中图分类号、文献标志码、文章编号、DOI、收稿日期、致谢、备注 |

### 10.2 交互规则

- 作者、单位、基金、作者简介均使用可增删行表格；
- 作者通过序号关联单位，支持一个作者多个单位；
- 通信作者可多个，但需明确标记；
- 基金开关默认关闭；关闭时输出不显示基金，但数据保留在项目中；
- 基金开关打开但无条目时：阻止生成或给出明确警告；
- 所有字段支持“从原文提取”与“手动修改”，并标记来源；
- 中图分类号、文献标志码、文章编号、DOI 为可选字段，由模板决定是否输出；
- 表单自动保存，不需要用户频繁点“保存”。

### 10.3 正文信息与表单冲突处理

**原则：M4 表单是生成用元数据的唯一来源；正文是候选和证据。二者可以并存，但生成时绝不重复输出。**

进入 M4 时：

- 自动从 M3 `metadata` 和正文中的题名、作者、单位、摘要、关键词、基金、作者简介块预填；
- 每个字段标记来源：`正文`、`AI 识别`、`手动修改`；
- 点击来源标签可定位到原文块；
- 正文块不删除，只标记为“已吸收”，仍可在原文对照中查看、回退。

字段级规则：

| 正文 | M4 表单 | 处理 |
|---|---|---|
| 有 | 空 | 自动预填；生成时用正文候选 |
| 有 | 有，内容相同 | 合并，无警告 |
| 有 | 有，内容不同 | 显示冲突提示；**默认表单优先**，正文块标记“已吸收” |
| 无 | 有 | 直接用表单 |
| 无 | 空 | 必填校验/警告 |

- 用户手动改过表单，视为明确覆盖；不得用正文静默覆盖回去；
- 冲突必须显示“与正文不同，正文块将被跳过”，不能静默；
- 提供“采用正文”“保留表单”“查看差异”三个动作；
- 正文作者/单位无法可靠拆分时，不能静默丢弃；显示“正文中有作者信息但未能拆分”，让用户选择“使用正文原样”或手动整理。

基金规则：

| 正文基金 | 基金开关 | 处理 |
|---|---|---|
| 有 | 开 | 用表单项目输出；正文基金块吸收，不重复 |
| 有 | 关 | 警告“正文检测到基金信息，但基金开关关闭”；确认后才允许不输出 |
| 无 | 开 | 用表单输出 |
| 无 | 关 | 不输出 |

作者简介、通信作者、邮箱按字段处理：表单有值时表单优先，正文块吸收；表单为空时回退正文；多作者、多单位按行合并，不整段覆盖。

保存与生成前：

1. 必填字段为空但正文有候选 → 自动回填并提示；
2. 表单与正文不一致且未确认 → 显示冲突摘要，生成前必须确认；
3. 基金开关关闭但正文有基金 → 必须二次确认；
4. 已吸收块从正文渲染中跳过，避免“正文一段作者、M4 又一段作者”。

### 10.4 模板决定展示位置

作者简介、基金、通信作者信息到底放首页脚注、题名页还是文末，由模板配置决定。界面只负责收集，不硬编码位置。

## 11. GB/T 7713.2-2022 与模板设计

### 11.1 必须说清楚的标准边界

GB/T 7713.2-2022《学术论文编写规则》主要规定：

- 论文的组成部分：前置部分、正文部分、附录部分；
- 题名、作者信息、摘要、关键词、正文、结论、致谢、参考文献等的要求；
- 编号、量和单位、插图、表格、数字、数学式、注释、科学技术名词等编排规则；
- 附录 B 给出字号和字体的**资料性**参考。

它不是一本“所有期刊统一版式”的固定模板。因此软件采用两层设计：

1. **规范检查层**：检查结构、编号、题注、摘要长度、关键词数量、参考文献格式等；
2. **版式参数层**：字号、字体、页边距、行距、单双栏等做成模板参数，允许学校/期刊覆盖。

软件文案不写“100% 符合国标”，而写“按 GB/T 7713.2-2022 组织内容与编排，并按模板参数生成版式”。

### 11.2 首版模板

首版**只内置一套“国标通用”模板**，单栏/双栏是它的两个参数组合：

| 模板 | 栏数 | 说明 |
|---|---|---|
| 国标通用（唯一内置） | 单栏 / 双栏 | 内容结构、字号字体按 GB/T 7713.2-2022；页边距、行距等未统一规定项使用模板默认值并允许调整 |

首版不内置“通用期刊版”“学校模板”，也不开放自定义模板导入 UI；但代码保留 `TemplateSpec` 注册接口，后续新增模板不改核心流程。

单栏/双栏是模板参数，不是两套独立代码。双栏时：

- 题名、作者、摘要、关键词默认通栏；
- 正文双栏；
- 跨栏图用 `figure*`，跨栏表用 `table*`；
- 强制 `[H]`、跨栏长表格等不支持的组合给出警告；
- 图表浮动策略可选“优先靠近引用处”或“模板默认”。

编号约定：

- **引言不编号**：标题只写“引言”，前面不加 0，也不加 1；正文各章从 1 开始（`intro_numbered=false`）；
- 节编号为 `2.1`、`2.2`、`3.2.1`，末位数字后不加点；
- 图、表、公式全文连续编号；
- 首版不提供“按章编号图表”的模板选项，后续模板扩展时再加反例提示。

### 11.5 规范检查（首版子集）

- 题名建议不超过 25 字（警告，不阻止）；
- 中文摘要建议 150–400 字（按摘要类型提示）；
- 关键词建议 3–8 个；
- 章节标题建议不超过 15 字；
- 引言不编号，后续章从 1 开始；
- 图/表编号连续且唯一；
- 图题在图下、表题在表上；
- 图表在正文中有引用；
- 公式编号连续；
- 参考文献在正文中有引用（若可解析）；
- 基金开启时必须有名称和编号；
- 双栏 + 跨栏长表格等不支持组合给出警告。

这些检查以“提示/警告/阻止”三级呈现，不擅自改用户内容。

### 11.6 参考文献结构化重排（已选 B）

处理链：

```text
提取参考文献原文
  → 大模型解析为结构化字段（只解析，不新增）
  → 程序校验 + 置信度标记
  → 用户在“参考文献”页逐条确认/修改
  → 生成 refs.bib
  → biber + biblatex-gb7714-2015
  → 输出 GB/T 7714-2015 顺序编码制参考文献表
```

#### 结构化字段

```json
{
  "id": "ref001",
  "original_text": "Bate R R, Mueller D D, White J E. Fundamentals of Astrodynamics...",
  "type": "book",
  "authors": ["Bate R R", "Mueller D D", "White J E"],
  "title": "Fundamentals of Astrodynamics",
  "publisher": "Dover Publications",
  "address": "New York",
  "year": "1971",
  "journal": null,
  "volume": null,
  "number": null,
  "pages": null,
  "doi": null,
  "language": "english",
  "confidence": 0.96,
  "missing_fields": [],
  "status": "confirmed"
}
```

支持类型：`article`、`book`、`inproceedings`、`incollection`、`phdthesis`、`mastersthesis`、`standard`、`patent`、`report`、`misc`。

#### 解析规则

- 模型只解析已有文字，**不补全作者、卷期、页码、DOI**；缺失字段必须留空并标记。
- 每条保留 `original_text`，用户可随时回退“保留原文”。
- 低置信度、缺关键字段、中英文混排的条目进入“待确认”。
- 用户可逐条修改、合并重复条目、调整顺序；编号按正文首次引用顺序重排。
- 若解析失败，该条回退为纯文本条目，不阻塞整篇编译。

#### 正文引用映射

- 优先识别数字引用：`[1]`、`[1,2]`、`[1-3]`、`［1］`；
- 映射为 `\cite{ref001}` / `\cite{ref001,ref002}`；
- 作者-年份制 `(Smith, 2020)`、`张三等（2021）` 首版只做候选识别，无法确定时保留原文并提示；
- 无法映射的引用不猜测，避免把 `[1]` 误当成公式编号或单位。

#### BibTeX 与样式

- 使用 `biblatex` + `biber`，样式 `gb7714-2015`；
- 中文文献写 `language = {chinese}`；
- 英文文献按原文字段输出；
- 生成前检查重复 key、空标题、空作者、非法字符；
- 编译命令按 12.2 的 biber 策略执行，不使用 `-halt-on-error` 阻断首遍。

#### 验收

- 样文的 5 条英文参考文献能完整解析并生成 `.bib`；
- 每条文献可追溯到 `original_text`；
- PDF 中参考文献编号与正文引用一致；
- 不出现模型凭空生成的作者、年份、卷期或 DOI；
- 解析失败时能回退纯文本，不丢条目。

## 12. LaTeX 生成、编译与错误处理

### 12.1 生成链路

```text
用户确认后的 DocumentIR
  + Metadata
  + Figure/Table 资源
  + TemplateSpec / Layout
        │
        ▼
程序校验（丢块、编号、资源、必填项）
        │
        ▼
LaTeX 转义 + 模板渲染
        │
        ▼
output/main.tex + assets/
        │
        ▼
latexmk -xelatex（或 xelatex 多遍）
        │
        ▼
日志解析 → PDF 预览 → 导出
```

### 12.2 编译命令

优先：

```powershell
latexmk -xelatex -interaction=nonstopmode -file-line-error -synctex=1 -outdir=build main.tex
```

若 `latexmk` 不可用：

```powershell
xelatex -interaction=nonstopmode -halt-on-error -file-line-error main.tex
```

按交叉引用/参考文献需要重复 2–3 次。使用 `biber` 时由 latexmk 调度；若缺少 biber，回退到手写 `thebibliography` 或提示安装。

**已实测的坑**：使用 `biblatex + biber` 且首次编译时，如果给 `latexmk` 加 `-halt-on-error`，第一遍可能因 `.bbl` 尚未生成而提前退出，返回非零，但实际后续能生成 PDF。因此：

- 有参考文献时不加 `-halt-on-error`，让 latexmk 继续跑 biber；
- 编译成功与否不只看退出码，还要检查 `main.pdf` 是否存在、日志是否出现 `Output written on main.pdf`；
- 如果退出码非零但 PDF 已生成且无 `Fatal error`，自动重跑一次 latexmk，再判断；
- 所有编译都保留完整日志，错误面板展示可操作信息，不直接丢英文日志给用户。

安全设置：

- 不启用 `shell-escape`；
- 编译工作目录固定在项目 `build/`；
- 不执行用户文本中的任意 LaTeX 命令；
- 首版模板只从应用内置目录加载；后续版本开放模板包导入时，再增加签名/结构校验；
- 图片路径做规范化，禁止 `..` 越界；
- 编译超时默认 120 秒，可取消；
- 日志中的 API Key、绝对用户路径做脱敏后显示；
- `algorithm` 块按“题注 + 预格式化行 + 行号”渲染（`algorithm` + `algorithmic`）；“输入/输出”行分别映射 `\Require`/`\Ensure`，不解析复杂 `for/if/else` 语义；解析失败时退化为带边框的预格式化块。

### 12.3 日志到用户提示

| 日志/问题 | 用户看到的提示 | 快捷动作 |
|---|---|---|
| `Font ... not found` | 缺少字体 XXX | 打开字体说明 / 切换替代字体 |
| `File ... not found` | 缺少宏包或图片 | 定位到图表 / 打开宏包安装说明 |
| `Undefined control sequence` | LaTeX 命令错误 | 显示行号和相关内容 |
| `Missing $ inserted` | 数学公式定界符不匹配 | 定位公式编辑 |
| `Overfull \hbox` | 内容超宽 | 提供缩字号/换行/跨栏建议 |
| `Too many unprocessed floats` | 浮动体过多 | 建议调整锚点/增加 `placeins` |
| 参考文献未解析 | 需要重新编译或检查 bib | 重新编译 / 检查条目 |
| 编译超时 | 编译未完成 | 查看日志 / 取消 |

首版只做确定性修复建议；不让 AI 自动改 `.tex`。后续可增加“AI 分析日志”，但必须由用户确认后才应用。

### 12.4 PDF 预览

实现方式：**pypdfium2（Apache-2.0）+ PDFium（BSD-3-Clause）+ Qt QImage/QPixmap**。不用 QtWebEngine，也不把 PDF 交给系统阅读器。

```text
main.pdf
  → pypdfium2 / PDFium 解析
  → 按“缩放 × DPI 缩放”渲染成位图
  → QImage / QPixmap
  → PageWidget
  → QScrollArea 纵向排列
```

- 以页面图片方式显示，支持 50%–300%、适应宽度、适应页面、页码跳转、Ctrl+滚轮；
- 按 `缩放比例 × devicePixelRatio` 渲染，避免高 DPI 模糊；
- 只渲染当前可见页及前后各 1 页，LRU 缓存，限制内存；
- 渲染在 `QThreadPool`，重新编译时取消旧任务；
- 编译成功后自动刷新，保留当前页码和缩放位置；
- 首版预览不参与编辑；不支持选中文字/搜索/复制；
- 渲染失败时提示“PDF 已生成，但预览失败”，提供“用系统阅读器打开”；
- 可选“在资源管理器中打开输出目录”。

> 为什么不用 QtPdf：QtPdf 文本选择/搜索更方便，但需要 PySide6-Addons，安装包更大。首版只需要检查版式，pypdfium2 更轻。若后续必须支持 PDF 文字选择，再评估 QtPdf 或 pypdfium2 + 透明文本层。

## 18. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 国标被误解为固定版式 | 用户期望“100% 符合”但实际因期刊而异 | 明确“结构规范 + 可配置版式”；提供参数核对表和模板覆盖机制 |
| 模型输出不稳定 | 结构错、漏块、JSON 失败 | ID 分类、Pydantic 校验、覆盖检查、重试、规则回退 |
| 参考文献解析错误 | 作者/卷期/页码被改错 | 保留原文、逐条确认、低置信度标记、缺失字段不补造、单条回退纯文本 |
| TXT/Markdown 信息量有限 | 标题、表格、图片结构需要推断或手动补充 | 推荐 Markdown；导入预览 + 待处理项；图片/表格必须由用户确认 |
| Markdown 方言差异 | 原始 HTML、远程图片、非标准表格解析失败 | 只支持 CommonMark/GFM；剥离 HTML；远程图片不自动下载；失败降级为文本 |
| LaTeX 编译脆弱 | 用户看到英文日志无从下手 | 固定模板、环境预检、日志中文化、错误卡片、最小可复现测试 |
| TeX 发行版差异 | MiKTeX/TeX Live 行为不同 | 同时测试两种；字体/宏包预检；路径可配置 |
| 双栏浮动体难控 | 图表位置不符合预期 | 明确“锚点非最终位置”；跨栏用 `figure*`；提供策略选项 |
| 打包体积/杀软误报 | 安装困难 | onedir、无 TeX 捆绑、代码签名、干净机测试 |
| API 隐私/费用 | 用户不敢用或费用超预期 | 明示发送范围、token 估算、本地模式、日志不存正文 |
| 正文与表单重复/冲突 | 作者、单位、基金重复输出或静默覆盖 | 表单为生成源、字段级来源标记、冲突显式确认、`consumed_block_ids` 跳过已吸收块 |
| 字体许可 | 不能随意分发商业字体 | 只用系统字体，不打包未授权字体 |
| 范围膨胀 | 延期 | 明确首版非目标；学校/期刊模板按需单独做 |

## 19. 最终确认与复核结论

### 19.1 已确认事项

以下按你的确认固定，不再反复询问：

1. **技术路线**：Python 3.12 + PySide6 桌面应用；
2. **AI 边界**：AI 只做结构识别，程序渲染 LaTeX，不让 AI 直接生成最终 `.tex`；
3. **模板**：首版只做“国标通用”，单栏/双栏作为参数；不内置期刊/学校模板；
4. **输入格式**：TXT、Markdown（`.md` / `.markdown`）；不支持 DOCX/DOC、PDF（含扫描版）作为正文输入；
5. **TeX 安装**：推荐 TeX Live（含清华镜像），检测 + 官方下载/winget 命令引导 + 手动选择路径，不静默提权安装；
6. **默认 API**：`https://api.deepseek.com` + `deepseek-flash`；Key 留空，用户填写并存 Windows 凭据管理器；
7. **官方文档**：<https://api-docs.deepseek.com/zh-cn/>；
8. **引言**：不编号，标题只写“引言”，前面不加 0；后续章从 1 开始；
9. **参考文献**：采用 **B. 结构化重排**，AI 解析 → 用户逐条确认 → `biblatex-gb7714-2015` + biber；
10. **图表/公式边界**：Markdown 管道表格/本地图片自动解析；TXT 图片靠上传、表格靠粘贴；子图不自动拆分；复杂表格有限支持；不处理 OMML；
11. **M2 范围**：TXT/Markdown 导入，约 **3–4 天**；不再实现 DOCX 解析。
12. **参考样文**：已放入 `参考论文例子/`，作为版式/结构参考和编译压力样例。
13. **正文/表单冲突**：M4 表单为生成源，正文为候选/证据；字段级冲突显式确认；已吸收块跳过，绝不重复输出。

### 19.3 参考样文分析与最后确认

样文：`参考论文例子/main_基于分层打靶的月球自由返回轨道高精度并行搜索方法_0930.tex`（12 页 PDF，2 图、4 表、1 个算法、9 个公式、5 条英文参考文献）。

它的参考价值：

- 单栏、A4、2.6/2.5 cm 页边距、11 pt 正文的版面节奏；
- 标题/作者/摘要/英文摘要/关键词/中图分类号的前置部分顺序；
- 图表题注、三线表、算法浮动体、公式编号、页眉“章标题 + 页码”；
- 5 条英文参考文献可作为 B 方案的第一组解析样例。

它**不能直接当作导入样例**：

- 它是 `.tex` + PDF，不是 TXT/Markdown；
- PDF 只编译了一遍，正文里的引用显示为 `[?, ?]`，交叉引用也未解析；
- 正文 11 pt、引言编号为 1，与本次确定的“5 号正文 + 引言不编号”不一致；
- 缺少单位、基金、作者简介等字段。

处理方式：

- **不修改你的原始文件**；
- 用它作为“目标版式参考”和编译压力样例；
- 另做一份脱敏的 TXT/Markdown 导入样例（保留标题、摘要、章节、图表位置、公式占位、参考文献），用于验收；
- 若你有该论文的 Markdown 或 TXT 版本，直接提供更好。

算法块的处理：首版支持“算法1 + 题注 + 预格式化行 + 行号”，可保留输入/输出和步骤；不自动解析 `for/if/else` 的伪代码语义。如果你要求完全还原 `algorithmic` 的语义排版，需要再增加 1–2 天。

### 19.4 不再需要确认的默认值

以下由我按方案确定，后续可在模板里调整：

- 基金开关默认关闭；关闭后不输出，但保留数据；
- 作者简介、基金、通信作者的展示位置由模板决定，默认放首页脚注/文末；
- 页面默认 A4、上下左右 25 mm、1.5 倍行距；
- 图题在图下、表题在表上，图表默认靠近引用处浮动；
- 页码默认页脚居中；样文的“章标题 + 页码”页眉作为可选项；
- 首版 PDF 预览不支持选中文字/搜索；只用于检查版式。
