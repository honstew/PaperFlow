# M5.5 可选 AI 模块

- 状态：可选模块，默认不启用；已实现“只读审阅 + 白名单自动修复”
- 依赖：已配置 API Key，且当前模型支持文本与图像输入
- 原则：**AI 只审阅、只建议；不直接生成或覆盖最终 `.tex`**
- 位置：M5 之后、M6 之前的可选增强

## 1. 模块包含什么

| 功能 | 入口 | 输入 | 输出 |
|---|---|---|---|
| AI 参考文献解析 | 参考文献页“AI 解析条目” | 参考文献原文文本 | 结构化字段，仍需人工确认 |
| AI PDF 版式审阅 | 生成导出页“AI 审阅 PDF” | PDF 页面图片 + 页面文本 | findings 列表 |
| 白名单自动修复 | 审阅结果选中条目 | findings + target 目录 | 受控 overrides + 重新编译 |
| 前后对比/回滚 | 修复后对话框 | 修改前/后 PDF | 保留或回滚 |
| 提示词 | `llm/ai_prompts.py` | 固定系统提示词 | 严格 JSON |

不包含：

- 自动改写论文正文；
- 自动修改 `main.tex` 的正文/命令；
- 自动补造参考文献、作者、数字或结论；
- 无 target 或不在白名单内的自动修改。

## 2. 启用方式

- 没有 API Key：两个 AI 按钮保持禁用，M5 原有流程完全不受影响；
- 有 API Key：按钮可用，但每次调用前仍需用户确认；
- 参考文献 AI 解析只发送参考文献原文；
- PDF 审阅发送渲染后的页面图片和页面文本，最多 20 页；
- 不把页面图片或正文写入日志。

## 3. AI 参考文献解析

实现文件：`src/paperflow/llm/reference_ai.py`

流程：

```text
本地规则结果
  → 用户点击“AI 解析条目”
  → 确认发送参考文献原文
  → deepseek-flash JSON Output
  → Pydantic/字段白名单校验
  → 合并回本地条目（缺失条目保留）
  → 仍需逐条确认并保存
```

保护：

- 只接受 `id` 已存在的条目；
- 类型限制在固定枚举；
- 空字段不覆盖本地已有值；
- AI 未返回的条目保留；
- 任何异常都不修改本地结果；
- 状态仍为“待确认”。

真实测试：

- 2 条示例参考文献；
- AI 返回 2 条，字段与原文一致；
- 未写入 Key 或正文日志。

## 4. AI PDF 视觉审阅

实现文件：

- `src/paperflow/llm/review_ai.py`
- `src/paperflow/ui/ai_review_dialog.py`

流程：

```text
main.pdf
  → pypdfium2 渲染 PNG（最多 20 页）
  → 页面文本 + 图片 + 版式参数
  → deepseek-flash 视觉审阅
  → findings JSON
  → 字段校验、页码校验
  → 审阅结果对话框（可选中白名单修复）
```

findings 字段：

```json
{
  "page": 2,
  "severity": "major",
  "category": "figure_overflow",
  "evidence": "图 1 右侧超出正文栏约 12 mm",
  "suggestion": "将图 1 宽度调整到 85%，或改为跨栏",
  "target": "figure:f1",
  "confidence": 0.86,
  "auto_fixable": false
}
```

校验规则：

- 页码必须在 1..页数；
- 严重度只允许 major/minor/info；
- 证据和建议至少有一项；
- 非法条目直接丢弃；
- 不执行任何字段中的命令；
- 不把 findings 自动写回 `main.tex`。

真实测试：

- 3 页示例 PDF；
- 返回 3 条 findings；
- 输入约 3056 / 输出约 349 tokens；
- 结果仅展示，未修改文件。

## 5. 提示词

提示词文件：`src/paperflow/llm/ai_prompts.py`

### 5.1 参考文献系统提示词要点

- 只能使用原文明确出现的信息；
- 不能猜测、不能补造；
- 一条输入对应一条输出，id 必须原样返回；
- 字段为空就留空；
- 只输出 JSON。

### 5.2 PDF 审阅系统提示词要点

- 只报告图片中确实可见的版式问题；
- 不改写正文，不评价学术质量；
- 每条必须有页码、严重度、类别、证据、建议；
- 如果程序提供了 target 目录，必须原样返回 `figure:f001`、`table:t001`、`heading:B0009`；
- 没有问题时返回空数组；
- 只输出 JSON。

提示词不是“让模型自由发挥”，而是把模型限制为**结构化审阅器**。

## 6. 白名单自动修复

第一阶段完成后增加了受控修复，但仍然**不直接改 `main.tex`**。

允许的动作：

- `figure_width`：图片宽度降低 0.15，范围 0.55–1.0；
- `figure_span`：图片改为跨栏；
- `table_span`：表格改为跨栏；
- `page_break_before`：指定标题前 `\clearpage`。

安全条件：

- 必须有可定位的 `target`，例如 `figure:f001`、`table:t001`、`heading:B0009`；
- 只有证据/建议中出现明确的“宽度/缩小/过宽/超出/跨栏/过窄/标题分页”等依据才动作；
- 只有“裁剪/缺箭头”等图片内容问题，不会自动缩宽；
- 表格没有“跨栏/过窄”依据时不会自动改；
- 所有修改写入 `content/overrides.json`；
- 重新渲染、重新编译；
- 弹窗展示修改前后 PDF；
- 用户点“保留修改”才保留，否则恢复原 TeX/PDF/overrides。

## 7. 为什么不做正文自动修改

自动修改正文的风险：

- 模型可能误判图片；
- 模型可能把“内容问题”误当“版式问题”；
- 直接改 `.tex` 可能破坏转义、宏包、引用；
- 重新编译后可能引入新问题；
- 无法可靠回滚。

因此正文、作者、参考文献、数字、公式和结论永远只提示，不自动改。

## 8. 与 M6 的关系

- M5.5 是可选增强，不阻塞 M6；
- 没有 Key、没有网络、模型不支持图像时，M6 仍可正常打包和验收；
- AI 审阅失败不能影响普通 PDF 生成；
- M6 的干净机验收应同时覆盖“AI 关闭”和“AI 可用”两种情况。
