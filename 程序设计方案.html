ASSISTANT:

建议采用 Python + PySide6 图形界面 + DeepSeek API + XeLaTeX 编译引擎，设计成一款本地运行的桌面软件。用户导入论文、补充作者信息和图表、选择模板后，软件完成内容结构识别、模板排版、编译预览，最终导出 .tex、PDF 及配套资源。

其中最关键的设计是：由 DeepSeek 识别论文结构，由可配置的 LaTeX 模板执行排版规则。这样能提高格式稳定性，也方便后续增加学校、期刊或会议模板。

下面按可直接进入开发的程度给出方案。

三、首次启动与 XeLaTeX 环境检测

首次启动显示两个主要区域：

  • DeepSeek 设置：API Key 输入框、显示/隐藏按钮、连接测试按钮、是否保存密钥。
  • 排版环境检查：XeLaTeX、编译辅助工具、必要宏包及模板字体的检查结果。

环境检查不能仅判断“是否安装过 LaTeX”，应执行实际验证。

检测项方法不通过时的处理
XeLaTeX 可执行文件查找路径并运行 xelatex --version引导安装或手动选择路径
宏包查询工具检测 kpsewhich提示修复发行版配置
模板所需宏包查询 ctex、fontspec 等实际依赖按发行版提供补装说明
模板所需字体查询字体并试编译提示安装字体或选择替代字体
编译能力编译一份最小中文测试文档显示诊断和修复建议

各系统安装引导建议如下：

平台可引导安装
WindowsTeX Live 或 MiKTeX
macOSMacTeX
Linux系统包管理器中的 TeX Live、XeTeX 和中文支持组件

软件提供“打开官方下载页”“查看安装步骤”“选择已有安装路径”“重新检测”按钮。首版不建议静默执行系统级安装；安装完成后重新检测即可。

API Key 通过一次小规模请求验证可用性，并明确提示该测试可能产生少量调用费用。密钥不写入论文项目、日志或导出文件。

四、文档导入与内容结构化

用户提到“先转成纯文本再输入模型”，这一流程可以保留，但需要同时保留原文件的结构信息，否则 DOCX 中的图片位置、表格结构和公式容易丢失。

建议导入后生成两份数据：

  • 供模型识别的文本：带有段落编号、图表占位标记的规范化文本。
  • 本地文档结构数据：保存原始段落、样式、表格单元格、图片、公式和来源位置。

例如，提供给模型的文本可采用：

TEXT
[P001] 基于深度学习的某某方法研究
[P002] 张三，李四
[P003] 摘要：本文……
[P004] 关键词：深度学习；……
[P005] 1 引言
[P006] 本文研究流程如图1所示。
[P007] 图1 研究流程
[P008] 不同方法的实验结果见表1。
[T001] 表1 不同方法的性能比较
[TABLE_DATA_001]

段落编号用于把模型识别结果与原文对应起来，也为后续定位错误、修改插图位置提供依据。

首版文件支持建议：

格式支持范围
.txt正文导入、编码识别、按文本识别章节与图表
.docx正文、常见表格、内嵌图片和基础样式
.doc提示用户另存为 .docx；后续可增加转换支持
PDF暂不作为首版主要输入格式

DOCX 公式、复杂合并表格、文本框和浮动图片需要单独处理。无法可靠转换的内容应进入“待处理项”，让用户补充 LaTeX 公式或调整表格，避免无提示丢失。

五、DeepSeek 的职责与调用方式

建议将模型任务限制为：

  1. 识别论文标题、摘要、关键词、正文、参考文献、致谢等区域。
  2. 识别章节层级。
  3. 识别图表题注、正文引用及可能的插入位置。
  4. 提取已有作者、单位、基金信息，供用户确认。
  5. 标记缺失或含义不明确的内容。

默认保持论文原文，不擅自润色、删减、补充结论或生成参考文献。若后续增加学术润色，应作为独立功能，并支持逐项确认修改。

模型返回结构化 JSON，由程序校验，例如：

JSON
{
  "sections": [
    {
      "level": 1,
      "title": "引言",
      "paragraph_ids": ["P006", "P007"]
    }
  ],
  "figures": [
    {
      "id": "fig_001",
      "source_label": "图1",
      "caption": "研究流程",
      "reference_paragraph_ids": ["P006"],
      "suggested_anchor_after": "P006",
      "needs_confirmation": true
    }
  ]
}

长论文采用“先识别整体结构，再按章节处理，最后汇总校验”的方式，并根据实际所选模型的上下文限制分块。模型调用失败后保留已完成结果，支持重试，避免重新处理整篇论文。

需要特别校验：

  • 模型引用的段落编号是否存在。
  • 正文是否出现遗漏或重复。
  • 图表编号是否冲突。
  • 作者和基金信息是否来自原文或用户输入。
  • 模型建议是否超出了排版任务范围。

六、排版标准与模板设计

默认提供“GB/T 7713.2—2022 学术论文编写规则模板”，但应区分两类配置：

  • 编写规则：论文组成、标题层级、摘要关键词、图表、注释等。
  • 版式参数：纸张、页边距、字体字号、行距、单双栏、页眉页脚等。

GB/T 7713.2—2022 不应被简化为一套固定的字体和页边距。具体参数应依据正式标准逐项核对；标准未统一规定或允许选择的部分，要标明模板默认值，并允许期刊或学校要求覆盖。参考文献著录规则也应独立配置，不能只根据论文编写规则推定。

模板选择界面可以提供：

配置项选项示例
模板国标基础模板、学校模板、期刊模板、自定义模板
栏布局单栏、双栏
双栏首页标题和摘要通栏、正文双栏；或模板指定形式
纸张与页边距模板默认、自定义
正文字体与字号模板默认、自定义
图表位置策略自动浮动、优先靠近引用处
双栏图表宽度单栏宽度、跨双栏
参考文献样式模板指定、用户选择

模板应独立成包，包含配置、LaTeX 文件、字体要求和示例文档。后续新增格式时主要增加模板，无需修改核心程序。

七、图表识别与输入窗口

这是整个软件的重要交互模块。建议设置一个“图表管理”页面，以列表展示自动发现的图表：

编号类型题注关联正文素材状态操作
图1图片研究流程第1节某段待上传上传、预览、定位
图2图片实验结果第3节某段已从 DOCX 提取替换、调整
表1表格性能比较第3节某段待确认编辑、导入、定位

识别采用 规则匹配 + 模型语义判断 + 用户确认。规则先查找“图1”“图 1”“表1”“见图1”等模式，模型再区分题注、正文引用和可能的插入位置。

同一张图可能被引用多次，因此不能每遇到一次“图1”就插入一张图片。系统应建立“一个图表对象对应多个引用位置”的关系。

每个图片编辑窗口包含：

  • 上传或替换图片，支持 PNG、JPG、PDF；其他格式可按需转换。
  • 中文题注、可选英文题注。
  • 建议插入位置及原文上下文。
  • 图片宽度、单栏或跨栏。
  • 图片来源或备注。
  • 清晰度与宽高比提示。

每个表格编辑窗口包含：

  • 从 DOCX 提取的可编辑表格。
  • 从 Excel/CSV 导入或粘贴单元格。
  • 手动新增行列。
  • 表题、表注、单位。
  • 三线表样式。
  • 自动换行、跨页及跨栏选项。

表格应尽量保存为结构化数据并生成 LaTeX 表格。 仅有截图的表格可以按图片导入，但需要提示其文字不可直接编辑。

同时要向用户说明：LaTeX 的图表通常采用浮动排版，“插入在某段之后”表示源码锚点和优先位置，最终页面位置会受剩余空间及模板规则影响。软件可提供优先靠近引用处的策略，但不应承诺所有图表都精确固定。

八、作者与基金信息窗口

建议使用可新增行的表单，支持多作者、多单位及对应关系。

信息组字段
论文信息中文标题、英文标题
作者姓名、英文姓名、单位关联、通讯作者标记
单位单位名称、城市、邮政编码、国家，可选英文信息
联系信息通讯作者邮箱
作者简介姓名、职称、学位、研究方向等，可按模板配置
基金启用开关、项目名称、项目编号，可添加多项
其他致谢、可选投稿信息

基金开关关闭时，输出中不显示基金条目；已填写内容可以保留在项目中，方便重新启用。作者简介、基金和通讯作者信息的具体展示位置由模板决定，例如首页脚注或文末。

九、LaTeX 生成、编译与错误修复

生成链路建议固定为：

TEXT
经用户确认的论文结构
        +
模板配置与作者信息
        +
图片和表格资源
        ↓
程序校验、LaTeX 特殊字符转义
        ↓
生成 main.tex 和资源目录
        ↓
latexmk 调用 XeLaTeX
        ↓
解析日志、检查交叉引用
        ↓
PDF 预览

如未安装 latexmk，可以直接调用 XeLaTeX 并按交叉引用需要进行有限次数的重复编译。使用文献管理工具时，再按模板增加相应编译步骤。

错误面板要将日志转成可操作的提示：

编译问题用户提示
缺少字体指出字体名称，提供替换或安装入口
缺少宏包指出宏包名称和对应安装方法
图片不存在定位到图表管理中的对应条目
表格过宽提供缩小字号、调整列宽或跨栏选项
交叉引用未解析重新编译或定位无效引用
LaTeX 语法错误定位源文件与关联内容，显示诊断信息

首版优先使用确定性的修复规则。后续可以让 DeepSeek 辅助分析有限范围的编译错误，但修改应经过校验，并限制自动修复次数。

编译在独立工作目录执行，设置超时，默认关闭 shell escape；导入文本和模型输出中的任意 LaTeX 命令不能直接作为可信代码执行。

十一、项目结构与导出内容

建议一个项目对应一个目录：

TEXT
论文项目/
├── project.json             # 项目配置和模板选择
├── source/
│   └── original.docx        # 原始文档副本
├── content/
│   ├── extracted.json      # 原始结构及来源信息
│   └── manuscript.json     # 用户确认后的论文结构
├── assets/
│   ├── figures/
│   └── tables/
├── template/               # 本项目使用的模板快照
├── output/
│   ├── main.tex
│   ├── main.pdf
│   └── references.bib      # 使用结构化文献时生成
└── build/                  # 编译中间文件和日志

导出支持三个入口：

  • PDF：用于阅读、提交和打印。
  • LaTeX 源文件：输出 .tex。
  • 完整源文件包 ZIP：包含 .tex、图片、文献数据、自定义类或样式文件，以及编译说明。

其中完整源文件包更适合后续修改和投稿，因为单独一个 .tex 通常无法包含图片等依赖。

十二、开发阶段与验收重点

建议分三阶段实施：

阶段实现范围验收重点
第一阶段：最小可用版本Windows、API 设置、环境检测、TXT/DOCX 基础导入、结构识别、作者/基金、手动图表匹配、国标基础模板、单双栏、PDF/TEX 导出一篇完整示例论文能从导入到导出，正文无遗漏，图表和作者信息正确
第二阶段：复杂论文支持DOCX 图片关联、复杂表格、公式、结构化参考文献、多模板复杂内容有可靠处理方式，无法识别的内容有明确提示
第三阶段：体验与扩展macOS/Linux、批量处理、模板管理、编译辅助修复跨平台表现稳定，模板与项目可迁移

第一阶段就应建立一组测试论文，覆盖中文特殊字符、多作者多单位、基金开关、重复图表引用、缺图、长表格和单双栏切换。验收既检查能否成功编译，也检查正文是否完整、引用是否一致，以及 PDF 是否符合已核对的模板规则。

按照这一方案，首版的核心交付应是：一个可保存项目、可核对模型识别结果、可补充图表和作者信息，并能稳定生成 XeLaTeX 源文件与 PDF 的桌面应用。国标模板的具体参数需在开发时依据正式标准和目标投稿要求建立规则清单，再落实到模板与验收样例中。
